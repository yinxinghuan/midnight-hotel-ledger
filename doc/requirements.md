# 《午夜酒店值班簿》需求文档

## 1. Overview

一款 2–4 分钟完成一局的竖屏生成式互动黑色喜剧：午夜酒店经理发现 307 号房浴缸通往海底，玩家连续三次用酒店礼仪认真接待章鱼住客，观看九段真人超现实短片并归档九个结果。

## 2. Visual Design

- 基准视口 390 × 844，短屏覆盖 320 × 568。
- UI 属于老牌精品酒店的午夜值班终端：酒红皮革、氧化黄铜、暖黑玻璃和米色打字纸。
- 问题页只保留三场进度、一句事故、同场共享首帧和三个短答案，取消需要解码的档案代码与冗余说明。
- 固定人物是欧美年轻女性夜班经理 Mara、年长白人男性住客和同一只紫色章鱼；三场保持酒红制服、黄铜材质与夜间冷暖光连续。
- 生成画面内部不出现文字、Logo、水印、字幕或终端 UI。

## 3. Game Mechanics

- 场景数：3；每场选择数：3；独立生成视频：9；可归档结果：9。
- 状态：`cover → setup → incident → footage → report → setup(next) / incident(retry) → complete`。
- 每场三个视频使用同一精确首帧；视频 `canplay` 后 180 ms 交叉淡入。
- 五拍时间点：确认 0 ms、预兆 650 ms、异常升级 2200 ms、稳定 4100 ms、归档 5200 ms。
- 第一场“浴缸传来海浪声”：塞排水口与呼叫维修为失败结果；“升级为海景套房”让章鱼触手拿到房卡并进入第二场。
- 第二场“章鱼没有证件”：要求护照与按八位住客收费为失败结果；“让八只触手分别签名”产生八张房卡并进入第三场。
- 第三场“八只触手同时按铃”：拔掉电话线与送八份早餐为失败结果；“请它接管夜班前台”让章鱼同时处理所有服务铃，Mara 下班，海水仍流进大厅。
- 失败只重试当前场；成功答案造成下一场问题。每次进场轮换答案顺序，不暗示正确位置。
- 视频目标时长 4.8–5.5 秒；解码失败仍使用对应尾帧进入结果。
- 归档键为 `<sceneId>:<outcomeId>`，写入 `midnight_hotel_ledger_reports_v2`。

## 4. Controls

- Pointer / Touch：开机、三个处置、声音、继续与重试使用 `onPointerDown`。
- Keyboard：`Enter` 开始、继续或重试；`1 / 2 / 3` 选择；`M` 切换声音。
- 触控目标至少 44 × 44 CSS px；录像播放时不接受重复选择。
- 全局禁止 iOS 长按 callout、图片拖拽和非编辑文本选择。

## 5. Win / Lose Conditions

- 失败处置看完完整录像后重试当前场；成功处置进入下一场。
- 第三场成功后进入完成页，显示章鱼接管前台和原始海水事故仍未解决的最终反转。
- 报告页显示结果标题、事故摘要、`新档案 / 已调阅`、`x / 9` 进度和继续或重试按钮。
- 集齐 9/9 显示“夜班值班簿封存”，但不阻止重玩。

## 6. Sound Effects

- 终端开机：90 → 240 Hz 正弦上滑，360 ms，音量 0.035。
- 处置确认：380 Hz 三角波，70 ms，音量 0.03。
- 水压预警：120 / 105 Hz 两次正弦脉冲，间隔 160 ms，音量 0.035。
- 海浪：80 → 46 Hz 噪声与低频包络，420 ms，音量 0.055。
- 房卡与签名：310 / 465 / 620 Hz 三音和弦，300 ms，音量 0.04。
- 八铃同时响：620–980 Hz 八个短正弦音，240 ms 内交错，单声部音量不超过 0.015。
- 归档盖章：72 Hz 方波撞击，160 ms；完成使用 262 / 392 / 523 Hz 和弦 480 ms；静音或 Web Audio 失败不阻塞视频。
